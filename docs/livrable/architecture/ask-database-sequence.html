8. Short oral explanation

8. Explication orale courte

This sequence begins with a question and a profile. The Gateway first checks whether that profile may call ask_database. The SQL service then loads only the semantic catalogue authorized for that profile. The analyzer may refuse the request, request clarification, select a fixed tool, or route a variable question to the generator. The generated SQL is only a proposal. It must pass AST validation and allowlists before PostgreSQL executes it with a profile-specific account, a read-only transaction and timeouts. Finally, the result is checked and returned with its SQL, parameters and versions. If the request is unsafe or unauthorized, the process stops before the database.
Cette séquence commence par une question et un profil. La Gateway vérifie d’abord si ce profil a le droit d’appeler ask_database. Le service SQL charge ensuite uniquement le catalogue sémantique autorisé pour ce profil. L’analyseur peut refuser, demander une clarification, choisir un outil figé, ou envoyer une question variable au générateur. Le SQL généré n’est qu’une proposition. Il doit passer la validation AST et les allowlists avant que PostgreSQL l’exécute avec un compte lié au profil, une transaction en lecture seule et des timeouts. Enfin, le résultat est contrôlé et renvoyé avec son SQL, ses paramètres et ses versions. Si la demande est dangereuse ou non autorisée, le processus s’arrête avant la base.
